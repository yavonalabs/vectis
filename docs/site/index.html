FROM REQUEST TO RECORDED CHANGE

“Could you update this record?”
There’s a place for that.

Start with a recurring support task. Developers choose the records, permissions and actions; operators use the resulting workspace.

  1. 01

    Find the right record

    Search, combine typed filters and follow related records. Give the person doing the work the context they need.

  2. 02

    Review the operation

    Use forms or configured Java actions. Supported actions show a preview; operators provide a reason before confirming.

  3. 03

    Check the outcome

    Review the updated record and permitted activity history, including the operator and reason recorded for the change.

BUILT AROUND YOUR APPLICATION

Your team knows the task.
Your code knows the rules.

Vectis runs alongside your Spring Boot application and JPA entities. Configure access and expose the operations you want people to use.

For tasks with business rules, expose a dedicated action. Generic record edits still require you to define the right validation and permissions.

A useful starting point

  • A Spring Boot team handling repeated record lookups and support changes.
  • Operators who need an interface for a defined set of tasks.
  • Developers who want to configure an in-app workspace.

Start with fictional data, then evaluate a small, permission-scoped workflow before introducing production writes.

A FEW GOOD QUESTIONS

Before you bring it to the team.

Why use Vectis when developers can write SQL?

Developers can write queries. Vectis gives other team members a repeatable interface for configured tasks, so every lookup or supported change need not start with a request to an engineer. Whether that helps depends on your actual workflow.

Where does our data go?

The starter runs inside the application where you install it and uses that application's persistence configuration. The planned public demo uses separate fictional records; it is not a service for connecting your production database.

Is this ready for production?

This is an early preview. Evaluate authentication, entity permissions, validation, audit storage and mutation behavior for your application. Hosted-demo testing does not establish readiness for your production workflows.
